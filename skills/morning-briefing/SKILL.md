# lifegame 朝のブリーフィング

lifegame の MCP サーバーに接続した状態で使う。「今日のブリーフィングをして」と依頼されたら、
まず `get_daily_summary` を1回だけ呼び出す。クライアントによってはツール名に接続名の接頭辞が付く
(`lifegame__get_daily_summary` など)。名前が一致しなくても、末尾が `get_daily_summary` の
ツールを使う。

日付や「今日」の境界はツールが返す `date` に従い、推測しない。サーバーは JST で判定している。

## 返す形式

日本語・簡潔・実行しやすい調子で、次の固定構成にする。

1. `## 今日（YYYY-MM-DD）` — 今日の全体像を1〜2文。`holidays` が空でなければ祝日名に触れる
2. `### 予定` — `events` を時刻順で列挙(`start_time`–`end_time` とタイトル)。
   `all_day` が true のものは時刻の代わりに「終日」と書き、先に並べる。なければ「なし」
   - `started_earlier` が true の予定は**前日から続いている**。`start_time` は前日の時刻なので
     開始時刻として書かない。「〜10:00 まで」のように終了時刻で書く
   - `ends_later` が true の予定は**翌日まで続く**。「22:00〜(翌日まで)」のように書く
3. `### 期限切れ` — `overdue_tasks` を優先度と期限つきで列挙。なければ「なし」
4. `### 実行予定を過ぎたタスク` — `scheduled_overdue_tasks` を優先度と実行予定つきで列挙。なければ「なし」
5. `### 今日が期限` — `due_today_tasks` を列挙。なければ「なし」
6. `### 今日の実行予定` — `scheduled_today_tasks` を時刻順で列挙。なければ「なし」
7. `### Inbox` — `inbox_count` 件。多い場合だけ整理を促す
8. `### 今日の完了` — `completed_today_tasks` を列挙。なければ「なし」
9. `### まずやること` — 重要度、期限、実行予定から、今すぐ着手する候補を最大3件。
   `events` の空き時間を踏まえて「◯時までに」のように現実的な提案にする

`open_tasks` は期限と実行予定の4つの未完了バケットを**重複を除いて**合わせたものなので、
別枠で列挙しない。1件に期限と実行予定の両方がある場合も、同じタスクを複数の節に出さない。
期限切れ/実行予定超過を今日分より優先し、同じ緊急度なら早い日付・時刻の意味を優先する。
両方を持つことが判断材料になる場合は、選んだ1行に `期限: … / 実行: …` と併記する。

`events` は Google カレンダーの予定、タスクは lifegame のもので、別の情報源。混ぜて数えない。

## 予定が無いとき / 取れなかったとき

3つの状態を区別する。

- **`events` キーが無い** — カレンダー連携が許可されていない(`calendar:read` スコープ未付与)。
  `### 予定` の節ごと省き、予定について何も言わない。「なし」とも書かない
- **`calendar_unavailable` が true** — 取得できなかった。`### 予定` に「取得できませんでした」と
  明記し、予定なしとして扱わない
- **`events` が空配列** — 本当に予定がない。「なし」と書いてよい

後ろ2つでは `まずやること` でも、空いていると断定せずに提案する。

## やらないこと

- タスクのタイトル・期限・メモを勝手に変更しない
- 完了・削除などの書き込みは、ユーザーが明示的に依頼したときだけ行う
- サマリーに無い情報を補わない。空なら「なし」と書く
